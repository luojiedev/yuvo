# 导入、导出与恢复设计

最后更新：2026-07-20

## 1. 两类能力

### 当前账本 JSON 备份

用于恢复知余账本，当前实现为 `swift-ledger-backup`、`formatVersion = 1` 的 `.json` 文件，内容包括：

- `backupId`、`exportedAt`、当前账本元数据。
- 账户、分类、子标签、流水、订阅及其版本字段。
- 当前设备已有的图片附件，以 Data URL 嵌入备份；整个导入文件限制为 20 MB。

禁止导出密码、会话令牌、邀请令牌、Push endpoint、Outbox 重试状态和设备密钥。

### 流水 CSV

用于 Excel、Numbers 或其他记账产品之间交换。UTF-8 BOM CSV 至少包含：

- 发生时间、收支类型、原币金额、币种、汇率、人民币结算金额。
- 主分类、子标签、账户、描述、是否参与统计、记录人。
- 知余流水 ID、账本 ID 和格式版本；外部文件没有这些字段时通过映射导入。

CSV 不承载图片、订阅规则、成员权限和完整账本结构，因此只用于流水交换。

## 2. 页面设计

入口放在“我的 → 数据与设置 → 导入与导出”，进入独立页面：

- 导出 JSON 备份：导出当前账本的业务数据和本机已有附件。
- 导出流水 CSV：导出当前账本未删除流水。
- 导入 JSON/CSV：导入到当前账本；先校验格式、数据 ID、分类/账户映射与附件，再逐项幂等写入本地 Outbox。

导入确认前不得写入数据。所有可输入控件在 iOS Safari/PWA 中实际字号不小于 16px。

## 3. JSON 备份幂等恢复

- `backupId` 在生成备份时固定，重复导出会产生新的 `backupId`。
- 备份内实体保留原 ID。导入时，ID 不存在则新增；ID 已存在且内容哈希一致则跳过；ID 已存在但内容不同则进入冲突预览，不静默覆盖。
- 每个恢复操作使用稳定 `operationId = restore:<backupId>:<entityType>:<entityId>`。同一备份重复提交或网络重试返回首次结果。
- 单个实体与对应 Outbox 在同一 IndexedDB 事务中提交。导入会先完成可执行的格式、映射和附件校验；若浏览器在写入期间发生配额或进程故障，可重新导入同一文件继续，已成功实体会被跳过。
- 导入完成后保存恢复报告，但不把整个原始备份长期存入 IndexedDB。

家庭账本恢复需要当前用户仍有对应账本的写权限。无权限或账本不存在时，允许将业务数据复制为新的私人账本，但必须在预览页明确显示 ID 和成员关系会被重新创建。

## 4. CSV 导入幂等性

- 对原文件字节计算 SHA-256，得到 `fileFingerprint`。
- 每一行使用 `csv:<fileFingerprint>:<rowNumber>` 作为稳定来源键；同一文件重复导入时跳过已经成功的行。
- 知余自己导出的 CSV 若包含流水 ID，则优先按实体 ID 和内容哈希判断，而不是按行号。
- CSV 内两行内容相同可能代表两次真实消费，不能仅按金额、时间和描述全局去重。
- 错误行生成可下载报告，包含行号、字段和原因；修正文件后视为新文件，用户可以在预览中决定是否导入。

## 5. 校验与安全

- JSON 与 CSV 导入文件均限制为 20 MB；备份中的流水和订阅 ID 不允许重复。
- JSON 使用明确 schema 校验，未知的未来主版本拒绝导入；兼容的小版本字段可以忽略并报告。
- 校验每个附件的 MIME、大小和 SHA-256；不信任文件扩展名。
- 描述、名称和 CSV 单元格按普通文本处理；CSV 导出时对以 `= + - @` 开头的文本做公式注入防护。
- 导入日志只记录 `backupId`、文件指纹前缀、数量和错误码，不记录完整描述或附件内容。

## 6. 金额与时间

- 新格式同时携带原币金额、人民币结算金额和汇率快照；旧格式只有 CNY 金额时按 1:1 升级。
- CSV 金额先解析为十进制定点数，再转换为最小单位整数，禁止使用二进制浮点数直接落库。
- JSON 备份保存 UTC 时间和原始账本日期语义；首版 CSV 导入只接受本应用导出的 ISO 时间格式，不猜测歧义日期如 `07/08/2026`。

## 7. 管理员灾备

Cloudflare D1 的 SQL 导出和 Time Travel 属于服务端灾备，不暴露给普通用户：

- 定期导出 D1 schema 和数据到受控 R2，并单独维护 R2 附件清单。
- D1 导出会阻塞其他数据库请求，应在低峰期运行并监控持续时间。
- 定期在隔离环境执行恢复演练，验证 D1 数据、R2 附件和哈希引用一致。
- SQL dump 不经过应用权限、版本迁移和 Outbox，因此不能从“我的”页面直接导入。

## 8. 已实现与后续增强

首版已经实现版本化 JSON、嵌入式附件、CSV 公式注入防护、文件指纹、重复导入跳过和 Outbox 同步。后续增强包括 ZIP 流式附件、导入预览与列映射、冲突报告、错误行下载、全账本打包以及管理员 D1/R2 灾备演练。

## 9. 验收重点

- 同一 JSON 备份连续导入两次，第二次全部跳过且不会产生重复 Outbox。
- 同一 CSV 连续导入两次不重复；CSV 中两条内容相同的真实流水仍会分别导入。
- 格式、映射或附件解析失败时不开始写入；写入阶段异常后可用同一文件幂等续传。
- 在具备对应分类和账户的目标账本中恢复后，流水、订阅和本机附件数量一致。
- 10 USD 的导出与恢复保留原币金额、汇率来源、快照时间和人民币结算金额。
