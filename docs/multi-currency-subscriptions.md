# 多币种与订阅管理设计

最后更新：2026-07-20

## 1. 产品边界

- 第一阶段只支持人民币（CNY）和美元（USD），每个账本的结算币种仍固定为 CNY。
- 外币账单同时保留原币金额和人民币结算金额。流水详情展示两者，统计、预算和订阅预测只使用人民币结算金额。
- 订阅表示未来会重复发生的扣费规则，流水表示已经发生的收支事实，两者使用独立实体。

## 2. 记账交互

金额卡片左侧的币种应为可点击按钮。点击后在 CNY 和 USD 之间切换；只支持两个币种时不需要打开完整选择页。

- CNY：只输入人民币金额，汇率固定为 1。
- USD：输入美元原币金额，并在金额卡片下展示“参考汇率”和“约合人民币”。页面打开时自动获取当日汇率，用户可以按银行卡实际入账价修改。
- 保存前必须明确显示最终人民币结算金额，避免用户误以为统计会按美元数值直接累计。
- 编辑历史账单时加载保存时的汇率快照，不使用最新汇率重算。

自动汇率与双币种在同一阶段交付，但不能成为离线保存的前置条件：优先请求 Worker 的同源汇率接口；失败时读取最近一次本地缓存；仍无缓存时要求用户输入。无论来源如何，都允许用户覆盖并保存来源和快照时间。

首选数据源为 Frankfurter v2 的 `USD/CNY` 日参考汇率。Worker 负责代理、校验和缓存上游响应，浏览器不直接依赖第三方服务：

- 请求示例：`GET /api/v1/exchange-rates/USD/CNY`。
- Worker 上游：`GET https://api.frankfurter.dev/v2/rate/USD/CNY`。
- 缓存键包含原币和结算币；成功结果缓存 6 小时，客户端另存最近一次成功结果用于离线回退。
- 响应包含 `base`、`quote`、`rateMicros`、`rateDate`、`source` 和 `fetchedAt`，不把 JavaScript 浮点数直接传入金额计算。
- 上游失败只影响自动带出，不阻塞记账；日志记录状态码和汇率对，不记录账单金额。

## 3. 账单数据模型

建议在现有账单上补充：

| 字段 | 含义 |
| --- | --- |
| `amountMinor` | 原币最小单位金额；CNY 分或 USD 美分 |
| `currency` | 原币，第一阶段为 `CNY` 或 `USD` |
| `baseAmountMinor` | 冻结的人民币结算金额，单位为分 |
| `exchangeRateMicros` | 1 原币兑换人民币的汇率，使用百万分之一整数保存 |
| `exchangeRateSource` | `fixed`、`manual` 或 `frankfurter` |
| `exchangeRateAt` | 汇率快照时间 |

历史记录增量迁移为 `baseAmountMinor = amountMinor`、`exchangeRateMicros = 1_000_000`、来源为 `fixed`。禁止使用浮点数直接参与持久化金额计算。

所有本地 Outbox、远端同步 payload、D1 schema、快照和增量变更必须同时支持这些字段。相同 `operationId` 重放时，原币金额、汇率和结算金额必须与首次请求一致。

## 4. 信息架构

- 流水、统计、预算：账本范围页面，保留全局账本切换器。
- 我的：账号和应用级页面，不展示全局“当前账本”顶栏。
- 我的 → 账本与记账 → 账本管理：负责切换、新建，后续承载改名、归档和成员管理。
- 我的 → 订阅管理：展示当前账本的订阅概览，因此入口副文案需标明当前账本；进入后可在页面内切换账本。

账本切换必须保留来源上下文：从个人中心进入则切换后仍在个人中心，从记账页进入则保留尚未保存的输入，从流水/统计/预算进入则停留原页。

## 5. 订阅实体

建议新增独立的 `Subscription`，至少包含：

| 字段 | 含义 |
| --- | --- |
| `id`、`operationId`、`ledgerId`、`version` | 身份、同步和乐观锁字段 |
| `name` | Apple Music、Apple Fitness+ 等服务名 |
| `beneficiary` | 使用人，例如“孩子”“我”“全家” |
| `accountId`、`categoryId` | 默认付款账户和支出分类 |
| `amountMinor`、`currency` | 每期原币金额 |
| `baseAmountMinor`、`exchangeRateMicros` | 预计人民币金额和汇率快照 |
| `frequency`、`interval` | 月、季、年及间隔数 |
| `nextChargeOn` | 下一次扣费的账本本地日期 |
| `remindDaysBefore` | 提前提醒天数 |
| `status` | `active`、`paused`、`cancelled` |
| `lastGeneratedPeriodKey` | 最近已生成周期，用于防止重复流水 |

受益人第一阶段使用自由文本即可，不与账号或家庭成员强绑定，否则孩子没有账号时会无法表达实际场景。

## 6. 订阅页面

订阅管理首页建议包含：

- 顶部汇总：本月预计扣费、未来 30 天扣费、有效订阅数量，金额均为人民币。
- 即将扣费：按日期排序，展示服务、受益人、付款账户、原币金额和约合人民币。
- 全部订阅：支持有效、暂停、已取消筛选。
- 新建/编辑：服务名、受益人、付款账户、分类、金额、币种、汇率、周期、下次扣费日、提醒时间。

下次扣费日使用系统日期选择器，避免移动键盘无法输入日期分隔符。确认扣费和取消订阅均需要二次确认；成功后在订阅页显示明确结果。未来日期的扣费流水仍正常保存和同步，但默认流水、统计、预算与日历到扣费日当天才展示或计入，搜索和导出仍可查询。

Apple Music 和 Apple Fitness+ 应创建为两条订阅规则，而不是仅在普通账单上勾选“周期账单”。普通账单上的现有“周期账单”标志后续可改为“保存后创建订阅”的快捷入口。

## 7. 生成流水与幂等性

第一阶段建议采用“到期确认”而非无感自动入账：到期时展示待确认扣费，用户确认后生成真实流水。这样可以处理涨价、扣费失败、试用延期和汇率变化。

生成流水使用稳定键 `subscriptionId + periodKey`，例如月订阅使用 `subscription-id:2026-08`。客户端 Outbox 和服务端数据库均对此键建立唯一约束：

- 同一周期重复点击、断网重试或多设备同时确认，只生成一笔流水。
- 生成的流水保存 `subscriptionId` 和 `subscriptionPeriodKey`，可从流水回到订阅。
- 修改订阅只影响尚未生成的周期，不重写历史流水。
- 取消订阅不删除历史流水。

## 8. 分阶段交付

### 阶段一：修正信息架构

- 个人中心移除全局账本顶栏，增加可点击的账本管理入口。
- 账本切换保留来源页面和未保存记账内容。

### 阶段二：CNY/USD 双币种与自动汇率

- 完成增量迁移、本地和 D1 字段、同步、金额换算领域测试。
- Worker 增加同源汇率接口、响应校验和缓存；客户端增加最近成功汇率缓存与离线回退。
- 金额卡片实现单击币种切换、自动带出汇率、人工覆盖和人民币结算预览。
- 流水、搜索、详情、统计、日历和预算全部改用正确金额口径。

### 阶段三：订阅管理

- 新增订阅本地实体、Outbox、D1 表、同步实体和管理页面。
- 实现受益人、周期、下次扣费、暂停/取消和人民币预测汇总。
- 实现到期确认生成流水及跨设备幂等测试。

### 阶段四：提醒与更多币种

- 使用现有 Web Push 能力发送续费提醒；通知投递失败不影响订阅状态。
- 将 CNY/USD 的币种常量扩展为可配置币种表，并按实际需要增加更多币种。

## 9. 验收重点

- 10 USD 按 7.20 保存后，统计和预算增加 72 CNY，而不是 10 CNY；详情仍展示 10 USD。
- 修改当前汇率不会改变历史账单的人民币结算金额。
- 完全离线时可以用最近汇率保存 USD 账单，恢复网络后幂等同步。
- 同一订阅同一周期在重复点击、超时重试和两台设备并发确认下只生成一笔流水。
- iOS Safari/PWA 中所有新增表单输入的实际字号不小于 16px，打开、聚焦、输入、失焦和关闭后页面缩放正常恢复。
