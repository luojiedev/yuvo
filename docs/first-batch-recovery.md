# 账号隔离与数据恢复

本文说明当前源码包含的账号隔离与恢复行为；实际部署需同步发布对应前端、Worker 和数据库迁移。

## 账号与账本隔离

- 新账号使用 `swift-ledger:user-<userId>` 独立 IndexedDB，访客使用 `swift-ledger:guest-v1`。
- 登录完成后切换账号空间并重新加载，退出先锁定空间再退出远端会话。账号账目与 Outbox 保留，重新登录同一账号后继续同步。
- 同一浏览器其他标签页收到空间切换事件后重新加载。
- 登录已有账号不再用快照覆盖已有账本，以免覆盖未同步修改。
- 切换账本或账号会使旧异步结果失效，A → B → A 也不能复用第一次 A 的结果。

## 旧版数据迁移（2026-09-09 已接入）

用户已确认：自动迁移能确认账号归属的数据，其余旧数据保留并锁定。

- 启动时只检查旧库是否存在数据；新安装不会因此创建旧库。旧库按原版本只读打开，不升级、不删除、不改写原记录。
- 首次升级且尚未选择账号时，可使用旧库保存的有效会话进行在线验证；显式退出后的访客状态不会自动登录回旧账号。登录原账号、网络恢复以及“检查旧数据”按钮都会触发重新检查。
- 迁移前通过 `/me` 验证用户和设备，再通过 `/ledgers` 确认当前账本权限；缓存中的用户 ID、账本名称和记录人名称都不能单独证明归属。
- 按账本整体迁移。已同步内容在确认权限后可迁移；未同步的新流水还必须满足旧会话与当前账号相同、创建人明确、只有一条创建操作且操作 ID 对应当前流水。旧更新、删除和配置操作缺少可靠修改人信息时，整个旧账本保留并锁定，云端已同步内容仍可按正常登录流程恢复。
- 未绑定账本、无权限账本、只读成员的未同步写入、修改人不明的操作、归属不明的附件上传、关联不完整的数据，以及目标空间已经有账本但没有迁移完成记录的情况，都不自动合并或上传。界面只显示汇总提示，不暴露其他账号的账本名称或内容。
- 迁移保留实体 ID、操作 ID、版本号、同步游标与附件字节；不复制旧账号令牌。数据、校验后的记录数量和迁移完成标记在目标库的同一事务内提交。
- 使用包含附件 SHA-256 的源数据指纹识别重复迁移；已迁移的数据不会覆盖目标空间中的新修改。两个标签页并发迁移只提交一份。源库在迁移期间或完成后发生变化时保留变化并提示锁定，不覆盖目标空间。
- 可用空间不足时停止复制；存储写入失败会回滚当前账本。之前已完成的账本保留完成标记，重新检查时安全跳过。图片依次计算摘要，避免一次将所有附件内容载入内存。
- 旧库始终保留，第一版不提供自动清理或将归属不明数据强行绑定账号的入口；这类内容需要后续单独核对。

## 同步问题处理

“我的 → 同步问题”显示失败和冲突项目。查看时通过鉴权接口 `/api/v1/sync/entity` 读取指定账本、指定项目的最新云端版本，不依赖快照的流水数量上限。

- 采用云端：在一个本地事务中保存恢复记录、结束该项目的旧操作并应用云端内容。
- 重新提交：使用新的操作 ID 与所比较的云端版本提交；再次发生并发更新时继续触发乐观锁。
- 保留本地副本：流水及本机图片使用新 ID 创建，解除订阅周期关联，再恢复原流水的云端内容。
- 比较后本地内容变化时拒绝处理，要求重新比较。所有操作均保留恢复记录，重复点击不会再次处理同一问题。
- 打开处理界面期间暂停当前页面的自动同步；其他标签页的修改由本地版本比较防护。
- 批量推送先对完整队列排序，再每批发送最多 50 项，持续处理到清空或遇到失败。

## JSON 完整恢复

- 导出直接读取本地数据库，包括停用账户、停用分类、子标签、预算、订阅、流水和附件。界面的“自定义”入口不是业务分类，不纳入备份。
- 附件未下载齐时拒绝声称已完成完整备份；导出与导入采用一致的 20 MB 限制。
- 导入先验证金额、日期、关联关系及附件内容，再通过单个 IndexedDB 事务写入业务数据、导入记录与 Outbox；失败全部回滚。
- 恢复到当前账本，保留目标账本名称、成员与权限。备份中的预算和同名配置会恢复；有待同步配置修改时拒绝覆盖。
- 跨账本恢复使用稳定映射重新分配实体与附件 ID，订阅周期关联一同映射。重复恢复跳过已存在流水及已处理配置。
- 历史停用配置先同步创建/更新，再同步关联流水，最后同步停用，避免因引用未建立导致失败。
- CSV 仍使用原有交换流程，本轮的完整恢复保证只针对 JSON。

## 验证范围

回归测试覆盖独立账号数据库、退出锁定、旧请求失效、同账号待同步修改保留、完整备份关联与附件、重复恢复、事务回滚、三种冲突处理、重复处理拒绝，以及超过 50 项的有序同步。Worker 集成测试覆盖精确版本读取和私人账本权限隔离。

旧版迁移测试使用版本 4 的旧库，覆盖原库和令牌不变、附件及操作 ID 保留、身份不匹配、断网/失效会话、其他私人账本、无法确认的修改、重复与并发迁移、目标冲突、写入失败回滚、空间不足、旧页面并发写入，以及显式退出后不自动恢复旧会话。

新增私人/家庭账本类型选择和登录时的本机账本接入选项。账本名称、类型选择和登录输入控件显式保持至少 16px。已在构建后的本地页面以 Chrome 390 × 844 视口检查本机账本表单的打开、聚焦、输入、失焦和关闭，以及登录接入选项；实际输入字号为 16px，布局正常。iOS Safari/PWA 真机缩放与登录后类型选择仍需在发布前验收。

## 本机账本接入与全账号同步

- “本机账本”包含全部账目、图片、账户、分类、子标签、订阅、预算和原始待同步操作。登录已有账号时可选择一并接入；创建账号时接入全部本机体验账本。已登录用户也可在账本管理中接入。
- 仅处理 `swift-ledger:guest-v1` 中未绑定的私人账本。归属不明的旧库继续走上文的只读验证迁移，不能通过此入口认领。
- 自动生成且从未记账或修改的体验占位账本不会反复上传，避免每次退出、登录都新增空账本；手动新建的空账本仍会接入。
- 先在源库记录所属账号并冻结，再把全部数据与移交回执原子写入账号库。源库保留锁定副本，不再出现在体验模式列表；失败后由同一账号重试，其他账号不能接管。回执防止重试覆盖账号中后续修改。
- 源库业务写入在同一事务中验证冻结状态，防止其他已打开页面在移交后继续改写。其他体验模式页面收到移交通知后重新加载。
- 新建账本默认私人，可离线创建；家庭账本仍需联网创建。私人账本首次同步先调用 `POST /api/v1/ledgers/private`，以稳定的账本 ID 幂等注册，再重放原始操作。重复注册不会重置内容；只有原所有者可重试，家庭账本不能借此改为私人账本。
- 同步覆盖当前账号的全部账本，同时发现并下载其他设备新增的账本。单个账本失败不会阻止其余账本，尚未注册的私人账本也计入待同步数。
- 测试覆盖多本接入、图片和操作 ID 保留、源库锁定、重复接入不覆盖、目标冲突后恢复、跨账号接管拒绝、注册中断重试，以及非当前账本的同步。
